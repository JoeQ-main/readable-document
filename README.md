# Readable Document

A small Windows tray utility. Click **Read document** in its tray menu and it
finds the PDF or text-heavy image you most recently had in front, pulls the
text out, and opens a restyled version that is easier to focus on and skim:
short lines, generous spacing, clear headings with an outline, bolded
lead-ins, highlighted numbers. Nothing is written to disk unless you press
**Save**, which writes a standalone HTML file.

The text is never reworded or summarized. Only its presentation changes.

## Install

Python 3.14 on Windows 10 or 11.

```bash
py -3.14 -m pip install -r requirements.txt
```

Image text (and scanned PDFs) use the OCR engine built into Windows. English
Windows installs ship with the English OCR pack. If a message says the pack is
missing, add it under *Settings → Time & language → Language & region →
English → Language options → Basic typing / OCR*, or run in an administrator
PowerShell:

```bash
Add-WindowsCapability -Online -Name "Language.OCR~~~en-US~0.0.1.0"
```

## Run

Double-click `ReadableDocument.pyw` (or make a shortcut to it; put the shortcut
in `shell:startup` to launch it at sign-in). A page icon appears in the tray.

1. View a PDF or image in any application.
2. Click the tray icon, then **Read document** (a single left-click on the icon
   does the same). Extra clicks while a pass is running are ignored.
3. A window titled *Readable: name* opens. Toolbar buttons change text size,
   line spacing, column width, dark mode, number highlighting and "bionic"
   bolding. Your choices are remembered for the next document.
4. **Save** writes the current view as `name-readable.html` to a location you
   pick. The saved file opens in any browser with the same look and the same
   toggles.
5. Close the window to discard it. You can open several at once. **Quit** in
   the tray menu exits.

## How it finds the document, and what it captures

The app remembers the last window you had in front that is not the taskbar,
desktop or Start menu. When you click **Read document** it tries, in order:

1. The window's process command line names a PDF or image file (SumatraPDF,
   Acrobat, Photos, Paint and similar). The file is read directly.
2. The window title contains a filename such as `report.pdf`. The file is
   looked up in Windows Recent Items, then in Downloads, Desktop and
   Documents (two folders deep); the newest match wins.
3. Otherwise the window itself is captured with the Windows `PrintWindow`
   call, which renders only that window's own contents, and the capture is
   OCR'd in memory. Nothing else on screen is captured and the image is never
   saved. If `PrintWindow` yields nothing (some GPU-rendered windows), the
   window is brought to the front and its rectangle is grabbed from the
   screen; the header line then says *screen region capture*.

The header line at the top of every reading window states which of these
happened, and flags OCR text as possibly containing errors.

When both the window title and the process command line name a file and they
disagree (a browser keeps the file it was launched with on its command line
forever), the title wins, because that is what you are looking at.

The reading window loads its page from memory over a loopback-only HTTP
server inside the app (random port, unguessable token per document, page
forgotten when its window closes). This avoids WebView2's 2 MB limit on
inline HTML, so long documents work; nothing is written to disk.

Supported files: `.pdf .png .jpg .jpeg .bmp .tif .tiff .webp .gif`.

Preferences live in `%APPDATA%\PDFHelper\settings.json`; unexpected errors are
logged to `%APPDATA%\PDFHelper\error.log`.

## Development

```bash
py -3.14 -m pip install -r requirements-dev.txt
python -m pytest
```

Test fixtures are generated by `python tests/fixtures/make_fixtures.py`
(needs Arial from the Windows fonts folder for the bullet glyphs).
`scripts/thread_check.py` verifies the pywebview + pystray threading setup;
`scripts/capture_check.py` captures whichever window you click within three
seconds and shows the result.

### Manual smoke checklist

- Tray icon appears after launching `ReadableDocument.pyw`.
- PDF open in Edge → file found by title, whole document shown.
- PDF open in SumatraPDF or Acrobat → file found via command line.
- PNG open in Photos → OCR text with the "OCR text" note.
- A web page in a browser → window capture + OCR, header says "captured from
  window".
- Save → file opens in a browser with the same look; Save button hidden there.
- Change Dark and text size, close, read again → settings persisted.
- No document window (fresh sign-in, nothing opened) → message box.
- The tray survives every error above.
